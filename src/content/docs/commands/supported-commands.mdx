## Internal Commands

The following commands are used internally by GLIDE clients during connection setup, reconnection, and session management.
They are not supported as first-class methods but are instead automatically handled by the clients.

**Connection & authentication**

* `AUTH` — Handled via connection configuration; re-sent automatically on reconnect
* `HELLO` — Used internally for RESP3 protocol negotiation and embedded authentication
* `SELECT` — Applied automatically based on configured database ID; re-sent on reconnect

**Client identification**

* `CLIENT SETINFO` — Automatically sets library name and version on every connection
* `CLIENT SETNAME` — Used internally to name management connections

**Replication protocol**

* `REPLCONF` — Internal replication commands; not applicable to client usage

## Deprecated Commands

Deprecated Valkey commands may not be supported by GLIDE's clients. Where a command has been deprecated by Valkey, GLIDE generally does not expose it as a first-class client method and instead recommends its successor. The table below lists these commands and their replacements.

| Deprecated Command     | Recommended Alternative       |
| ---------------------- | ----------------------------- |
| `HMSET`                | `HSET`                        |
| `SLAVEOF`              | `REPLICAOF`                   |
| `GEORADIUS`            | `GEOSEARCH`                   |
| `GEORADIUSBYMEMBER`    | `GEOSEARCH`                   |
| `GEORADIUS_RO`         | `GEOSEARCH`                   |
| `GEORADIUSBYMEMBER_RO` | `GEOSEARCH`                   |
| `RPOPLPUSH`            | `LMOVE`                       |
| `BRPOPLPUSH`           | `BLMOVE`                      |
| `PSETEX`               | `SET` with the `PX` option    |
| `CLUSTER SLAVES`       | `CLUSTER REPLICAS`            |
| `CLUSTER SLOTS`        | `CLUSTER SHARDS`              |
| `QUIT`                 | Close the connection / client |
| `SYNC`                 | `PSYNC`                       |

If you rely on a deprecated command, please check the [Valkey documentation](https://valkey.dev/docs/commands) for the latest information on command deprecations and alternatives.

## Commands Available Through Options

Some commands are not exposed as client methods because their behavior is fully covered by options on a more general command. Instead of a dedicated method, use the alternative shown below.

| Command  | Use Instead                                    |
| -------- | ---------------------------------------------- |
| `GETSET` | `SET` with the `GET` / return-old-value option |
| `SETEX`  | `SET` with the `EX` (expiry) option            |
| `SETNX`  | `SET` with the `NX` (not-exists) option        |
| `SUBSTR` | `GETRANGE`                                     |

## Incompatible Commands

* `DEBUG`: Not supported.
* `PSYNC`: Incompatible with GLIDE's multiplexed connection model (server enters replication stream mode after `+FULLRESYNC`, corrupting subsequent requests)
* `SHUTDOWN`: Only available for on-premise Valkey, and is a dangerous command if not use correctly. We do not plan to support this command unless there's a strong use case for it. 
* `CLIENT REPLY` — Would break the multiplexed response protocol.
* `CLIENT UNBLOCK` — Requires internal connection/client IDs not exposed to users.
