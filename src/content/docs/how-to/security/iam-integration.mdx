GLIDE 2.2+ provides built-in support for **AWS Identity and Access Management (IAM)** authentication when connecting to **Amazon ElastiCache** and **MemoryDB** clusters. This feature automatically handles token generation and rotation, making it simple to maintain secure connections.

:::caution[GLIDE 2.2+ Required]
For GLIDE versions below 2.2, see the [guide](/how-to/security/iam-integration-using-aws-sdk) on how to configure IAM authentication using the AWS SDK.
:::

## How It Works

* GLIDE automatically generates **temporary authentication tokens** that are valid for **15 minutes**
* GLIDE **refreshes the token every 5 minutes** (default). On failure, it retries with **exponential backoff** and keeps using the **last valid token** until a new one is obtained
* When a new token is available, GLIDE updates its cached credentials. New and reconnecting connections use the fresh token, while pooled and isolated connections reconcile token changes before an eligible command
* During reconnection, GLIDE **checks whether the cached token has expired** (age ≥ 15 minutes). If so, it generates a fresh token before attempting to reconnect, ensuring a valid credential is used even when connections have been idle
* GLIDE handles **re-authentication** automatically when required, for example when ElastiCache or MemoryDB terminates a session after its maximum lifetime
* GLIDE handles all **token management**, **refresh operations**, and **re-authentication** behind the scenes
* On-demand token refresh is available via **`refreshIamToken`** (see [On-Demand Refresh](#on-demand-refresh) below)

## Required Setup

1. **AWS Credentials**: Unless you configure a [custom AWS credential provider](#custom-aws-credential-providers), your application must run in an environment where the default AWS credential chain can find credentials, such as an **EC2 instance with an IAM role** or an **ECS task with a task role**.

2. **TLS**: IAM authentication requires TLS. GLIDE rejects an IAM client configuration when TLS is disabled.

3. **Required Information**:

* **username**: Your ElastiCache/MemoryDB username
* **cluster\_name**: Your cluster's name
* **service**: Either **ElastiCache** or **MemoryDB**
* **region**: The AWS region where your cluster runs
* **refresh\_interval\_seconds (Optional)**: How often to refresh the token. Default is **300 seconds (5 minutes)**

The cluster name and region must not be blank, and the username must not be empty.

:::note
If `refreshIamToken` is called on a client that was not configured with `IamAuthConfig`, an error is raised at call time.
:::

## Custom AWS credential providers

Python, Java, Node.js, and Go direct clients can obtain AWS credentials from an application callback instead of the default AWS credential chain. Use this for credential stores or custom assume-role flows that the default chain cannot resolve.

The provider must return a non-blank access key ID and secret access key. A session token and expiration time are optional. GLIDE can invoke the provider during client creation, token refresh, or reconnection, so it must return current credentials and tolerate repeated calls.

:::caution[Direct clients only]
Custom IAM credential providers are not supported by client pools. Pool creation rejects a configuration that contains one. Omit the provider to use IAM authentication with the default AWS credential chain in a pool.
:::

## On-Demand Refresh

You can call `refreshIamToken` (or language equivalent) at any time to immediately request a fresh token from AWS and update the internal token cache.

:::note[What this does and does not do]
`refreshIamToken` **generates a new token and caches it**. It does **not** immediately re-authenticate an ordinary established connection. New and reconnecting connections use the refreshed token, while pooled and isolated connections reconcile it before an eligible command.

A successful refresh returns `"OK"` (in C#, `RefreshIamTokenAsync` completes without a value). If the credential provider or token signing fails, the method returns the error to the caller and the previously cached token remains in use.
:::
