To ensure system stability and prevent out-of-memory (OOM) errors, Valkey GLIDE limits the maximum number of concurrent (inflight) requests sent through each connection of a GLIDE client.

## Configuration

Inflight requests limit can be configured through the general client configurations.

<ClientTabs>
  <ClientTab slot="csharp">
    :::note[Release availability]
    The inflight requests limit is not included in the C# 1.1.0 client. Support is planned for **1.2.0**; its implementation has merged into `main` in [#509](https://github.com/valkey-io/valkey-glide-csharp/pull/509).
    :::

    ```csharp
    using Valkey.Glide;
    using static Valkey.Glide.ConnectionConfiguration;

    // Limit to 1000 inflight requests per connection
    var config = new ClusterClientConfigurationBuilder()
        .WithAddress("address.example.com", 6379)
        .WithInflightRequestsLimit(1000)
        .Build();

    await using var client = await GlideClusterClient.CreateClient(config);
    ```

    `WithInflightRequestsLimit` takes a `uint` and throws `ArgumentOutOfRangeException` when passed `0`.
  </ClientTab>

  <ClientTab slot="go">
    :::note[Release availability]
    The inflight requests limit is not included in the Go 2.5.3 client. Support is planned for **2.6.0**; its implementation has merged into `main` in [#6580](https://github.com/valkey-io/valkey-glide/pull/6580).
    :::

    ```go
    import (
        "context"

        glide "github.com/valkey-io/valkey-glide/go/v2"
        "github.com/valkey-io/valkey-glide/go/v2/config"
    )

    func ConnectClusterWithInflightRequestsLimit() {
        // Limit to 1000 inflight requests per connection
        myConfig := config.NewClusterClientConfiguration().
            WithAddress(&config.NodeAddress{Host: "address.example.com", Port: 6379}).
            WithInflightRequestsLimit(1000)

        client, _ := glide.NewClusterClient(myConfig)

        client.Ping(context.Background())
    }
    ```
  </ClientTab>

## Why Limit Inflight Requests

Excessive inflight requests can lead to queuing within the GLIDE infrastructure, increasing memory usage and potentially causing OOM issues.
By capping inflight requests per connection, this feature reduces the risk of excessive queuing and helps maintain reliable system performance.
The default inflight request limit is 1000 per connection, though this value can be configured in the GLIDE wrappers that expose it to suit application needs.

The limit is designed based on Little’s Law, ensuring that the system can operate efficiently at peak throughput while allowing a buffer for bursts.

* **Maximum request rate:** 50,000 requests/second.
* **Average response time:** 1 millisecond.

Using Little’s Law:

* **Inflight requests** = (Request rate) × (Response time)
* **Inflight requests** = 50,000 requests/second × (1 ms/1000 ms) = 50 requests

A default value of 1000 allows for sufficient headroom above this calculated baseline, ensuring performance during short bursts of activity.
When the inflight request limit is exceeded, excess requests are immediately rejected, and errors are returned to the client.
